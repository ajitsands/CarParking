Cloud ANPR Integration Guide

How Local Network ANPR Cameras Post Webhook Events to the Cloud Server (parking.sandslab.com)

1. The Cloud Webhook URL

When your application is hosted on the cloud (e.g. parking.sandslab.com or your VPS IP), the ANPR cameras on your on-premises local network (e.g. 192.168.1.X or 192.168.100.X) communicate with the cloud by pushing outbound HTTP POST requests to this designated endpoint:

Cloud ANPR Camera Webhook Endpoint
https://parking.sandslab.com/api/v1/webhook/anpr
Parameter Production Cloud Setting Local LAN / Testing Fallback
Protocol HTTPS (or HTTP) HTTP
Target Host / Domain parking.sandslab.com 192.168.100.4 (Local PC IP)
Port 443 (HTTPS) or 80 (HTTP) 8000 or 8081
HTTP Method POST POST
URI / Request Path /api/v1/webhook/anpr /api/v1/webhook/anpr

2. Architecture & Real-Time Data Flow

Why does this work without port forwarding on your local router?
In modern networks, all routers allow Outbound Internet Traffic (NAT). When a car approaches a gate, the local camera makes an outbound request across the Internet to the cloud server, exactly like an office computer browsing the web. No public IP or open incoming firewall ports are needed on the local camera switch.

🌐 End-to-End Parking Flow (Local Hardware ⟷ Cloud System)
Step 1

Vehicle Approach & LPR

Vehicle enters entry/exit lane. ANPR Camera (Dahua / Hikvision on 192.168.1.100) recognizes plate in < 50ms.

Step 2

Outbound Cloud Webhook

Camera sends HTTP POST with plate JSON metadata to https://parking.sandslab.com/api/v1/webhook/anpr.

Step 3

Cloud Decision Engine

Backend validates whitelist/staff, active parking sessions, grace period, or calculates tariff fee in < 80ms.

Step 4

Gate Action & Display

Android Display Tablet (polling cloud every 2s) displays vehicle fee & QR. Local barrier relay triggers open.

✓ Zero Local Router Configuration Required: Because cameras push data outward, you do not need a static public IP at the hospital, DDNS, or router port-forwarding. As long as the camera switch has outbound Internet access (DNS 8.8.8.8), webhooks will work 24/7.

3. Camera Configuration Procedures (Cloud Webhook Mode)

A. Dahua ANPR ITS Cameras (DHI-ITC413 / ITC237 / ITC215)

  1. Open browser and login to the Dahua camera web console (e.g., http://192.168.1.108).
  2. Ensure DNS is configured under Setting → Network → TCP/IP:
    • Preferred DNS: 8.8.8.8
    • Alternate DNS: 1.1.1.1
  3. Go to Setting → Network → Access Platform → HTTP Push (or Alarm Server):
    • Enable: Checked / ON
    • Protocol: HTTP or HTTPS
    • Destination Server / IP: parking.sandslab.com
    • Port: 443 (for HTTPS) or 80 (for HTTP)
    • Request Path / URL: /api/v1/webhook/anpr
    • Method: POST
    • Data Format: JSON
    • Upload Pictures: Check Plate Cutout and Overview Picture.
  4. Click Save & Apply.

B. Hikvision DeepinView / Traffic IPC (DS-2CD7A / iDS-TCM403)

  1. Log into the Hikvision camera web manager.
  2. Ensure Gateway and DNS (8.8.8.8) are configured under Configuration → Network → Basic Settings.
  3. Navigate to: Configuration → Network → Advanced Settings → HTTP Listening (or Alarm Server):
    • Destination Address: parking.sandslab.com
    • Port: 443 (or 80)
    • URL Path: /api/v1/webhook/anpr
    • Protocol: HTTP/HTTPS POST
    • Picture Upload: Enabled
  4. Under Road Traffic → Vehicle Detection, set region to Bahrain / GCC.
  5. Click Save.

C. Uniview / Hanwha / External LPR Software (Plate Recognizer / OpenALPR)

  1. Open the Webhook / Integration settings of your LPR software.
  2. Set Webhook URL: https://parking.sandslab.com/api/v1/webhook/anpr
  3. Set Method: POST (JSON format).

4. Webhook JSON Payloads & Server Response

The cloud backend automatically parses all standard camera manufacturer payload formats:

Standard JSON Payload (Sent by Camera or Local Agent):

{
  "gate_id": "GATE-IN-01",
  "plate_number": "123456",
  "confidence": 98.5,
  "direction": "ENTRY",
  "vehicle_type": "Car",
  "vehicle_color": "White",
  "timestamp": "2026-09-11 19:30:00"

{
  "success": true,

5. Barrier Control & Exit Display Board in Cloud Setup

Option 1: Direct Camera Alarm Out to Barrier (Standard Hardware Link)

The ANPR camera has a built-in relay dry-contact output (Alarm Out). Wire this contact directly to the Boom Barrier controller's Open input. When the camera recognizes the plate, it fires the physical pulse locally while simultaneously notifying the cloud server.

Option 2: Android Exit Gate Display Board / Kiosk App

The Android tablet mounted on the exit lane is configured with Server URL: https://parking.sandslab.com.

  • It continuously polls /api/v1/kiosk/status?gate_id=GATE-OUT-01 every 2 seconds.
  • When a car is detected by the camera and processed on the cloud, the tablet instantly displays the plate number, duration, fee, and dynamic BenefitPay / QR payment code.
  • Once payment is confirmed, the Android app sends the pulse to open the barrier.

6. Troubleshooting & Diagnostics

⚠️ If the camera is not sending events to the cloud:
1. DNS Check on Camera: Ensure the camera has a valid DNS server configured (e.g. 8.8.8.8). If the camera has no DNS, it cannot resolve domain names like parking.sandslab.com.
2. Test with Browser: Open https://parking.sandslab.com/api/v1/webhook/anpr in any web browser. You should receive an active JSON status message.
3. Test with cURL on Local PC: Run the command below from a computer on the same local network as the cameras.

Quick Diagnostic cURL Command:

curl -X POST https://parking.sandslab.com/api/v1/webhook/anpr \
  -H "Content-Type: application/json" \
  -d '{"gate_id":"GATE-IN-01","plate_number":"BAH-99887","direction":"ENTRY"}'

UNIVERSAL & HIMS INTEGRATION SPECIFICATION

Universal 3rd-Party & HIMS / HIS API Integration & QR Printing Manual

Bilateral REST Integration for Real-Time Parking Capacity, Booking Ingestion, Dynamic QR Slip Printing & Visitor Validation for ANY Software

1. Architectural Overview & Workflow

The Hospital & Facility Parking Management System provides dedicated, high-performance REST APIs for bilateral integration with ANY external software system. While commonly used for Hospital Information Systems (HIMS / HIS / EHR), these standard APIs integrate seamlessly with Clinic Management Systems (CMS), ERPs, CRMs, Hotel PMS, Valet & Visitor Gate Desks, Mobile Apps, or custom web appointment schedulers.

🏥 Hospital Info Systems (HIMS / HIS / EHR) 🩺 Clinic Management Systems (CMS) 🏢 Enterprise ERP & CRM 🏨 Hotel & Valet PMS 📱 Mobile & Web Booking Portals 🎟️ Self-Service Kiosks
🔄 End-to-End Bilateral Integration Workflow

⚙️ Dynamic QR Token Prefix from Settings or Request: The system generates secure QR tokens formatted as {PREFIX}-{IDENTIFIER}-{TIMESTAMP}-{RANDOM}. The prefix is dynamically retrieved from System Settings → QR Token Prefix (e.g. QR-KIMS, QR-PARK, QR-HOSPITAL, QR-VIP, or custom). External software can also pass a custom token_prefix in the JSON request body to override it per department or platform. If unconfigured, it safely defaults to QR-KIMS.
⚡ Base Server Endpoint: All APIs are available under http://<PARKING_SERVER_IP>:8000/api/v1/his/ (or your configured production domain https://parking.sandslab.com/api/v1/his/).

GET 2. Real-Time Parking Availability & Floor Status API

HIMS, CMS, digital outdoor signage boards, or visitor mobile apps can call this API periodically to fetch the live parking availability, total capacity, occupied spots, and floor-wise slot breakdowns.

Endpoint: GET /api/v1/his/parking-status

Query Parameters:

Parameter Type Required Description
(none) - No Returns overall facility parking capacity, occupied count, available slots, occupancy rate, and floor-wise breakdown.
plate_number string No Lookup a specific vehicle plate (e.g. BHR 43210) for current entry time, duration, and validation status.
patient_mrn string No Lookup vehicle status linked to patient / visitor ID or MRN (e.g. MRN-88192).

POST 3. Universal Booking Ingestion & Printable QR Code API

When an appointment or visit is confirmed in HIMS, Clinic Software, ERP, Mobile App, or Web Booking engine, the external software calls this endpoint. The parking system creates the appointment record, generates a unique secure QR token (using custom prefix from Settings or payload override), produces a high-resolution Base64 PNG and SVG vector image, and returns the printable payload immediately so the software can print it on thermal slips, patient passes, or send via WhatsApp / SMS.

Endpoint: POST /api/v1/his/appointments/sync

Content-Type: application/json

Request Body Fields:

Field Type Required Description
patient_mrn string Yes Medical Record Number, Visitor ID, or User Reference (e.g. MRN-88192 or VIS-1044).
patient_name string Yes Full Name of the patient / visitor (e.g. Ahmed Al-Sayed).
patient_phone string Optional Contact phone number (e.g. +973 3611 0022).
doctor_name string Optional Attending consultant / host / doctor name (e.g. Dr. Tariq Al-Hashimi).
department string Optional Department or clinic name (e.g. Cardiology, Pediatrics, VIP Lounge).
appointment_datetime string Optional Appointment date & time in YYYY-MM-DD HH:MM:SS format. Defaults to current timestamp.
registered_plate_number string Optional Vehicle plate number if known (e.g. BHR 43210). Enables automatic ANPR match upon arrival.
free_hours integer Optional Free parking duration granted upon QR validation (default: 3 hours = 180 mins).
token_prefix string Optional Custom token prefix for this request (e.g. QR-CMS, QR-PARK, QR-VIP). If omitted, uses System Settings or default QR-KIMS.

Sample JSON Request:

{
  "patient_mrn": "MRN-88192",
  "patient_name": "Ahmed Al-Sayed",
  "patient_phone": "+973 3611 0022",
  "doctor_name": "Dr. Tariq Al-Hashimi",
  "department": "Cardiology",
  "appointment_datetime": "2026-09-12 14:30:00",
  "registered_plate_number": "BHR 43210",
  "free_hours": 3,
  "token_prefix": "QR-KIMS"
}

POST 4. Consultation Checkout & Direct Validation API

If the doctor, nurse, receptionist, or cashier clicks "Complete Consultation" or "Invoice Paid" inside HIMS / external software, the system can automatically validate the patient's parking session without requiring manual QR slip scanning.

Endpoint: POST /api/v1/his/validate-visitor

Sample JSON Request:

{
  "patient_mrn": "MRN-88192",
  "plate_number": "BHR 43210",
  "appointment_code": "APT-20260912-7A9B1"
}

Sample JSON Response:

{
  "success": true,
  "data": {
    "session_code": "SESS-20260912-0014",
    "plate_number": "BHR 43210",
    "status": "VALIDATED",
    "message": "Parking session SESS-20260912-0014 for vehicle BHR 43210 validated successfully via HIMS consultation checkout."
  }
}

POST 5. Emergency Ambulance & VIP Priority Access API

Used for emergency inbound ambulances, doctor rapid response, or VIP emergency room codes to instantly open the inbound boom barrier and record high-priority audit logs.

Endpoint: POST /api/v1/his/emergency-access

Sample JSON Request:

{
  "plate_number": "AMBULANCE-04",
  "gate_id": "GATE-IN-01",
  "reason": "Trauma Emergency Inbound"
}

6. Visitor Validation Scanning Methods

The parking management portal supports three simultaneous validation methods to accommodate all patient and visitor workflows:

Method A: Scan Appointment QR

Patient presents the printed thermal slip or digital phone pass generated from HIMS / CMS / App. The clinic desk or kiosk scans the QR using a 2D barcode scanner or camera.

Endpoint: POST /api/v1/validation/qr

Method B: Reception Desk Manual

For patients without an appointment QR code. The receptionist enters the vehicle plate number and MRN directly in the web portal to authorize free parking.

Endpoint: POST /api/v1/validation/reception

7. Multi-Platform Integration Code Examples

1. JavaScript / Node.js (Axios / Fetch):

const axios = require('axios');

async function syncParkingAppointment(patientData) {
  try {
    const response = await axios.post('http://192.168.1.100:8000/api/v1/his/appointments/sync', {
      patient_mrn: patientData.mrn,
      patient_name: patientData.name,
      doctor_name: patientData.doctor,
      department: patientData.department,
      registered_plate_number: patientData.plate,
      free_hours: 3,
      token_prefix: 'QR-KIMS' // Optional: Custom prefix (or leave empty to use Settings default)
    });

    const qrImageBase64 = response.data.data.qr_png_base64;
    const qrToken = response.data.data.qr_token;
    console.log('Generated Parking QR Token:', qrToken);
    return response.data.data;
  } catch (error) {
    console.error('Parking Sync Error:', error.response?.data || error.message);
  }
}

2. C# / .NET (HttpClient):

using System.Net.Http;
using System.Text;
using System.Text.Json;

public async Task<string> GenerateParkingQrAsync(string mrn, string name, string plate)
{
    using var client = new HttpClient();
    var payload = new {
        patient_mrn = mrn,
        patient_name = name,
        registered_plate_number = plate,
        free_hours = 3
    };
    var content = new StringContent(JsonSerializer.Serialize(payload), Encoding.UTF8, "application/json");
    var response = await client.PostAsync("http://192.168.1.100:8000/api/v1/his/appointments/sync", content);
    var jsonString = await response.Content.ReadAsStringAsync();
    return jsonString;
}

import requests

8. Thermal Slip Printer Integration Guidelines

When printing patient consultation slips or appointment receipts on 80mm or 58mm POS thermal printers (Epson ESC/POS, Zebra ZPL, Citizen, Bixolon, Star Micronics):

  • Base64 PNG Direct Print: Convert qr_png_base64 to a bitonal bitmap image and send via standard ESC/POS raster graphics command (ESC * or GS v 0).
  • Native Thermal QR Command: If using native printer QR commands, pass the qr_token string to printer function GS ( k.
  • Recommended QR Dimension: 150px × 150px to 240px × 240px (minimum 25mm on physical thermal paper) for instantaneous 100% scanning rate.
